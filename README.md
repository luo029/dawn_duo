# 项目名称：契约 (Dawn Duo)

## 🚨 核心开发规范 (AI 代码生成要求)
为了保证后续迭代的效率与阅读体验，**所有 AI 生成的代码必须严格遵守以下要求**：
1. **禁止高亮**：必须使用 ```text 代码框包裹，**绝对禁止使用 javascript 或其他高亮标记**，方便用户直接复制。
2. **全文输出**：任何文件的修改，必须提供该文件的完整全文，绝对禁止使用 `...` 或省略号代替原有代码。
3. **极致精简**：代码需高度压缩，能在一行写完的逻辑绝不换行（前提是不破坏可读性），合并冗余变量，去除无用注释。
4. **逻辑清晰**：按照功能模块高度划分，UI 显示需严格根据当前 `identity`（身份）自动过滤无关设置项。
5. **UI 规范**：说明性文字不要过长，尽量使用 `<span class="help-icon" data-tip="...">i</span>` 包裹悬浮提示，保持按钮和主要操作直观。
6. **大白话总结**：每次修改后，必须在末尾提供一段**大白话总结**，简单说明修改了哪里，让小白也能秒懂。
7. **文件名位置**：输出任何文件全文时，**文件名必须写在 ```text 代码框之外**，代码框内只放文件内容；绝对禁止把文件名、路径、说明文字放进代码框内部。多个文件必须分别标注文件名并分别输出完整全文。

## 📁 文件存储与架构说明
本项目分为**两个仓库**：
1. **前端代码仓**（`dawn_duo`）：包含所有的 HTML/CSS/JS 文件以及 `index.html`。
2. **数据与后台脚本仓**（`dawn_duo_data`）：存放打卡记录 JSON 及后台推送脚本。

**注意**：为了方便本地一次性编辑和 AI 读取，`send-push.js` 和 `push.yml` 虽然最终运行在 `dawn_duo_data` 仓库，但也同步存放在本地的 `github_dawn_duo_data` 文件夹下。在提交时，需将这两个文件上传到云端仓库。云端数据交互逻辑由前端通过 GitHub API 直接读写。

### 🛠️ 设置面板架构重构（重要规范）
为了防止由于 `settings.js` 过大导致的代码难以维护以及白屏崩溃，设置面板已进行彻底解耦拆分。**所有拆分文件必须平铺在 `js/` 目录下（绝对禁止放入子文件夹，防止路径错误导致白屏）**。
拆分的文件结构如上目录树所示。其中：
- `js/settings-render.js`：负责拼装 DOM 并注入页面，内部包含防崩溃保护（使用 `safeCall` 包裹），即使某个 Tab 加载失败，也不会影响整体页面白屏。
- `js/pickers.js`：全局接管并美化了原生 `input[type="time"]` 和 `input[type="date"]`，实现了自定义滚轮时间和日历弹窗。

## 📝 文案变量占位符大全
在编辑通知文案、打卡弹窗文案时，可以使用以下占位符，系统会在发送时自动替换：
- `{name}`：当前用户的名字（如：主人、小狗、先生、宝宝）
- `{time}`：当前的具体时间（如：`23:15`）
- `{time_s}`：带秒的具体时间（如：`23:15:30`）
- `{date}`：当前的日期（如：`11月11日`）
- `{weekday}`：当前的星期（如：`周六`）
- `{shichen}`：当前十二时辰（如：`子时`）
- `{shichen_time}`：时辰的时间段（如：`23:00-01:00`）
- `{shichen_organ}`：当令经络（如：`胆`）
- `{duration}`：超时了多久（格式：`2 h 30 m`，仅限超时警告场景）
- `{mins}`：超时的纯数字分钟（如：`150`，仅限超时警告场景）

## 核心架构与工作流

### 1. 数据同步机制 (云端交互)
- **前端直连**：用户输入 GitHub PAT 验证，随后前端直接调用 GitHub API 读写私有库 `dawn_duo_data`。
- **四文件分离**：
  - 打卡记录：`master_records.json` / `doggy_records.json`
  - 发情记录：`master_heat.json` / `doggy_heat.json`
  - 配置文件：`config.json`（双端共享）
- **本地偏好隔离（核心重点）**：为了保证双方设备体验独立，所有属于“界面展示”的开关**均不参与云端同步**。例如：显示发情卡片、显示对方卡片、日历展示模式、时钟排版、简单模式、页面通知开关等，全部由本地 `localStorage` 控制。拉取云端数据时会被保护不被覆盖，上传时也会被剔除。
- **差异对比**：前端设有比对弹窗，在拉取或上传前比对本地与云端数据，且上传成功后**不会自动关闭设置面板**，方便连续修改。
- **强制同步触发**：在打卡完成后，前端在调用 GitHub Actions 触发对方通知前，会**强制先同步一次本地数据到云端**，防止云端脚本拉取到旧数据导致“防误触”机制错误拦截。

### 2. 通知与推送机制 (双通道)
系统分为**本地通知（页面内）** 与 **云端后台推送（Web Push）** 两种机制，互不冲突：
- **本地通知（页面内）**：
  - 基于 `Notification API`。网页必须开着才能收到。
  - 适用于：到点提醒、页面超时警告、对方打卡状态的动态检测。
  - 测试方法：已移除原先简陋的测试按钮，统一整合至“推送测试中心”选择本地渠道发送。
- **云端后台推送（Web Push）**：
  - 依赖 GitHub Actions 触发 `send-push.js`，即使锁屏或关掉网页也能收到。
  - 测试面板：支持预览与云端完全一致的文案效果，并支持选择“目标设备”进行定向测试推送。
- **发情推送专属逻辑**：
  - 触发：当一方记录发情时，前端先同步数据，再触发 GitHub Actions 发送推送。
  - 附带感受：如果开启【发情推送附带感受】且填了内容，推送正文将**直接使用你的感受内容**，不再拼接随机文案，也不加任何前缀。未填则默认留空。

### 3. 界面与权限规则
- **操作权限严格分离**：
  - 无论是主界面的“打卡”还是“发情”卡片，都**只能操作自己的**。如果对方卡片可见，会标注“只读”且按钮禁用。
  - 身份选择为“滴滴（both）”时，解锁所有操作权限。
  - 设置面板中的“发情记录修正”亦遵循此权限逻辑。
- **发情记录维护**：
  - 在修改今日发情时，弹窗内新增了“取消今日发情”按钮，一键撤销并恢复禁欲天数计算。
  - 实时状态同步：保存发情后，主界面UI、设置面板的修正列表会同步刷新。
- **主仆分离文案**：在“主仆”模式下，“熬夜警告”与“赖床警告”支持为“主人”和“小狗”分别定制；打卡修正界面中，小狗的状态会自动显示为“服从/抗命”。
- **性能优化**：移除了多余的 `transform: translateZ(0)` 硬件加速层，抛弃了 `setInterval`，改用 `requestAnimationFrame` 驱动主时钟，大幅提升滑动手感。统一采用基于 CSS 渲染的高性能滚轮和日历。

## 📝 本次更新日志（Bug 修复与体验优化）

在近期的代码审查中，修复了以下隐藏问题并进行了性能优化：

1. **主界面日历不渲染 Bug（修复）**：`checkin.js` 中的 `render()` 函数调用了一个未定义的 `renderHeatCycle()` 导致控制台报错并阻断了后续 `renderHistory()`。已移除该废弃调用，改为 `if (window.updateHeatUI) window.updateHeatUI();`。
2. **手机切后台耗电优化（优化）**：`app.js` 的时钟定时器加入了 `document.hidden` 判断，网页切到后台或锁屏时暂停主时钟更新，大幅降低手机耗电。
3. **云端日志无限膨胀与超时限制失效（致命修复）**：
   - `send-push.js` 新增了每天自动清理过期 `push_log.json` 记录的机制，防止文件无限膨胀。
   - `push.yml` 修复了漏传 `push_log.json` 的致命 Bug。之前因为没有提交日志，导致云端每次运行都“失忆”，**“每天最大超时提醒次数”设置完全失效**。现已改为与 `subscriptions.json` 一起提交。
4. **动态下拉框不刷新（修复）**：`custom-select.js` 和 `settings-msgs.js` 修复了动态刷新 `<select>` 的 `<option>` 时，自定义下拉框 UI 不更新的问题。现在测试推送面板的设备列表能正常刷新了。
5. **只读状态不够明显（优化）**：`checkin.css` 给对方“只读”卡片增加了置灰和降低透明度的样式，现在一眼就能看出对方的打卡按钮不能点。
6. **重复函数定义覆盖隐患（修复）**：`settings.js` 和 `settings-general.js` 中重复定义了 `applyIdentityFilter()`。已删除 `settings.js` 中多余的代码，保留 `settings-general.js` 中的定义。
7. **全局 DOM 监听卡顿优化（优化）**：`pickers.js` 用于监听时间/日期输入框的 `MutationObserver` 加入了 `100ms` 防抖，避免频繁弹窗或切换时引起页面滚动卡顿。
8. **旧版 iOS 导出图片崩溃（兼容性修复）**：`export.js` 新增了 `CanvasRenderingContext2D.prototype.roundRect` 的兼容补丁，防止在 iOS Safari 16 以下版本导出图片时报错崩溃。
