# 项目名称：契约 (Dawn Duo)

## 🚨 核心开发规范 (AI 代码生成要求)
为了保证后续迭代的效率与阅读体验，**所有 AI 生成的代码必须严格遵守以下要求**：
1. **禁止高亮**：必须使用 ```text 代码框包裹，**绝对禁止使用 javascript 或其他高亮标记**，方便用户直接复制。
2. **全文输出**：任何文件的修改，必须提供该文件的完整全文，绝对禁止使用 `...` 或省略号代替原有代码。
3. **极致精简**：代码需高度压缩，能在一行写完的逻辑绝不换行（前提是不破坏可读性），合并冗余变量，去除无用注释。
4. **逻辑清晰**：按照功能模块高度划分，UI 显示需严格根据当前 `identity`（身份）自动过滤无关设置项。
5. **UI 规范**：说明性文字不要过长，尽量使用 `<span class="help-icon" data-tip="...">i</span>` 包裹悬浮提示，保持按钮和主要操作直观。
6. **大白话总结**：每次修改后，必须在末尾提供一段**大白话总结**，简单说明修改了哪里，让小白也能秒懂。
7. **文件名位置**：输出任何文件全文时，**文件名必须写在 ```text 代码框之外**，代码框内只放文件内容；绝对禁止把文件名、路径、说明文字放进代码框内部。多个文件必须分别标注文件名并分别输出完整全文。

## 📁 文件存储与架构说明
本项目分为**两个仓库**：
1. **前端代码仓**（当前仓库）：包含所有的 HTML/CSS/JS 文件以及 `index.html`。
2. **数据与后台脚本仓**（`luo029/dawn_duo_data`）：存放打卡记录 JSON 及后台推送脚本。
**注意**：为了方便本地一次性编辑和 AI 读取，`send-push.js` 和 `push.yml` 虽然最终运行在 `dawn_duo_data` 仓库，但也同步存放在本地的项目根目录下。在提交时，需将这两个文件上传到云端仓库。云端数据交互逻辑由前端通过 GitHub API 直接读写。

### 🛠️ 设置面板架构重构（重要规范）
为了防止由于 `settings.js` 过大导致的代码难以维护以及白屏崩溃，设置面板已进行彻底解耦拆分。**所有拆分文件必须平铺在 `js/` 目录下（绝对禁止放入子文件夹，防止路径错误导致白屏）**。
拆分的文件结构如下：
- `js/settings-general.js`：外观、身份、模式、纪念日等。
- `js/settings-profiles.js`：双人名字、标签、颜色、按钮文字。
- `js/settings-rules.js`：作息时间、时区、时钟排版、日历等。
- `js/settings-notify.js`：通知渠道、后台推送开关、提醒项。
- `js/settings-msgs.js`：弹窗文案、通知文案、随机文案库、导入库、变量说明。
- `js/settings-data.js`：测试模式、推送设备管理、云端同步、本地导入导出。
- `js/settings-fix.js`：打卡记录修正、点击快速切换状态。
- `js/settings-modals.js`：设置面板关联的所有子弹窗 HTML 模板。
- `js/settings-render.js`：负责拼装 DOM 并注入页面，内部包含防崩溃保护（使用 `safeCall` 包裹），即使某个 Tab 加载失败，也不会影响整体页面白屏。
- `js/settings.js`：核心交互逻辑（保存、读取、开关联动等）。
- `js/pickers.js`：全局接管并美化了原生 `input[type="time"]` 和 `input[type="date"]`，实现了自定义滚轮时间和日历弹窗。

## 📝 文案变量占位符大全
在编辑通知文案、打卡弹窗文案时，可以使用以下占位符，系统会在发送时自动替换：
- `{name}`：当前用户的名字（如：主人、小狗、先生、宝宝）
- `{time}`：当前的具体时间（如：`23:15`）
- `{time_s}`：带秒的具体时间（如：`23:15:30`）
- `{date}`：当前的日期（如：`11月11日`）
- `{weekday}`：当前的星期（如：`周六`）
- `{shichen}`：当前十二时辰（如：`子时`）
- `{shichen_time}`：时辰的时间段（如：`23:00-01:00`）
- `{shichen_organ}`：当令经络（如：`胆`）
- `{duration}`：超时了多久（格式：`2 h 30 m`，仅限超时警告场景）
- `{mins}`：超时的纯数字分钟（如：`150`，仅限超时警告场景）

## 核心架构与工作流
### 1. 数据同步机制
- **前端直连**：用户输入 GitHub PAT 验证，随后前端直接调用 GitHub API 读写私有库 `dawn_duo_data`。
- **双文件分离**：`master_records.json` 和 `doggy_records.json` 分离记录，前端根据身份推送/拉取各自数据；`config.json` 存放双端共享配置。
- **差异对比**：前端设有比对弹窗，在拉取或上传前比对本地与云端数据，且上传成功后**不会自动关闭设置面板**，方便连续修改。
- **强制同步触发**：在打卡完成后，前端在调用 GitHub Actions 触发对方通知前，会**强制先同步一次本地数据到云端**，防止云端脚本拉取到旧数据导致“防误触”机制错误拦截。

### 2. 通知与推送机制
- **页面内通知**：基于 `Notification API`，利用 `sw.js` 和前端轮询判断是否到达打卡时间。
- **后台云端推送 (Web Push)**：前端获取 Push Subscription 并发送至 Cloudflare Worker 写入 `subscriptions.json`。GitHub Actions 每天定时触发 `send-push.js` 发送通知，遇到 404/410 自动清理失效订阅。
- **测试面板定向测试**：测试面板在触发云端推送时，可以下拉选择“目标设备”，云端脚本会精准匹配并只给该设备发送测试推送。
- **玩法拓展（待开发）**：
  - **任务/指令式通知**：触发特殊的推送，点击后唤起前端执行特定任务。
  - **压迫式催促**：利用 `{duration}` 变量，超时越久，推送文案越严厉（如从“小狗该睡了”变为“⚠️ 已经熬夜 1 小时，明天要挨罚了”）。

### 3. 界面与动态变量
- **主仆分离**：在“主仆”模式下，“熬夜警告”与“赖床警告”已从通用池中分离，支持为“主人”和“小狗”分别定制专属的警告文案；打卡记录修正界面中，小狗的状态会自动显示为“服从/抗命”。
- **自定义选择器**：废弃了原生丑陋的日期和时间选择弹窗，统一采用基于 CSS 渲染的高性能滚轮和日历。
- **性能优化**：移除了页面中多余的 `transform: translateZ(0)` 硬件加速层（防止 PC 端显卡崩溃卡顿），并且抛弃了 `setInterval`，改用 `requestAnimationFrame` 驱动主时钟，大幅提升滑动手感。
